## Паспорт ПС

| Поле | Значение |
|---|---|
| Название ПС | Медицинская система поддержки принятия врачебных решений **«МедЭксперт»** (СППР) |
| Предметная область | амбулаторный приём: обследование, предварительная диагностика, план лечения |
| Актёр | Врач (роль одна; на PDOM представлен клиентским модулем — АРМ) |
| Архитектура | клиент-сервер: много АРМ врачей → три серверных модуля-одиночки (регистрация, диагностика, лечение) |
| Внешняя сущность (КТ1) | Внешняя МИС — поставляет медкарты; аптечный сервис появится на последующих этапах (IDEF0/DFD) |
| Хранилище | местная БД (D1) — не сущность PDOM, появится на DFD |

## Модель КТ1 (PDOM)

- **Управляющие (5):** Врач · Внешняя МИС · Модуль регистрации · Модуль диагностики · Модуль лечения.
- **Управляемые (6):** Данные пациента · Медкарта · Показание · Предварительный диагноз · Обследование · План лечения.
- Управляющие между собой не связаны — взаимодействие только через данные.
- Агрегации: Обследование ◇ Содержит Предварительный диагноз, Обследование ◇ Включает План лечения.

## План дальше (сквозной проект)

- ЛР2 — прецеденты: актёр Врач, использование по функциям A1–A3.
- ЛР3 — требования качества.
- ЛР4 — IDEF0: А-0, А0 (A1–A3), уровни 2; сюда же вернутся аптечный сервис и местная БД (D1).
- ЛР5 — DFD: процессы 1–3 = A1–A3, накопитель D1.
- ЛР6 — диаграммы классов и последовательностей на базе PDOM.

## Соглашения (проверять перед сдачей)

- Управляющие сущности связаны только через данные; между управляющими — ни одного ребра.
- Глаголы связей одного модуля не повторяются.
- Формулировки «предварительный диагноз», «проект плана лечения» — везде одинаковые: система предлагает, врач решает.

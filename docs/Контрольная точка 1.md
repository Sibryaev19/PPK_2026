# Материалы для ЛР1 (контрольная точка 1) — ПС «МедЭксперт»

> Задание: предложить ПС для сквозного проекта; описать основное назначение; предложить название; определить цель и задачи разработки; разработать PDOM-диаграмму.

## 1. Предлагаемая ПС

Предметная область — амбулаторный приём пациента в медицинском центре. Проблема: за один короткий приём врачу нужно опросить пациента, получить показания диагностических приборов, восстановить историю болезни, сопоставить всё это с медицинской базой и назначить лечение. Данные разнородны и приходят из разных источников (слова пациента, приборы, внешние базы), а рутинный поиск и сопоставление информации съедает время приёма и провоцирует ошибки.

Предлагаемая ПС — **система поддержки принятия врачебных решений (СППР)**: программа берёт на себя сбор и структурирование данных обследования, их анализ и подготовку проекта плана лечения. Финальное решение всегда за врачом — система предлагает, врач решает: система не оказывает медицинских услуг, а готовит для врача данные. Пациент не является пользователем системы — все данные вводит врач со своего АРМ. Архитектура клиент-серверная: АРМов много (по одному на врача), серверная часть одна — три модуля обработки (регистрации, диагностики, лечения).

Три функции верхнего уровня:

1. **Обследование** — оформить карту пациента (из внешней МИС) и показания в единый документ-обследование.
2. **Диагностика** — проанализировать карту и показания, сформировать рейтинг диагностических гипотез; врач подтверждает одну как предварительный диагноз.
3. **Лечение** — подготовить проект плана лечения по подтверждённому диагнозу; врач корректирует и утверждает.

Границы системы (чего ПС не делает): не ведёт расписание и запись на приём, не считает оплату, не управляет приборами, не общается с пациентом, не ставит диагноз и не назначает лечение самостоятельно.

## 2. Название ПС

**Основной вариант:** «МедЭксперт» — медицинская система поддержки принятия врачебных решений (СППР).

Запасные варианты: «Диагност», «МедАналитик».

## 3. Основное назначение ПС

ПС «МедЭксперт» предназначена для поддержки принятия врачебных решений на амбулаторном приёме: сбора и структурирования данных обследования (сведения о пациенте, показания — приборные и выявленные врачом), формирования предварительного диагноза на основе истории болезни и базы схожих обезличенных случаев, а также подготовки проекта плана лечения с назначениями. Пользователи ПС — врачи, работающие через АРМ; решения утверждает врач, система их готовит.

## 4. Цель разработки ПС (SMART)

**Формулировка цели:** в течение 6 месяцев после внедрения ПС «МедЭксперт» сократить время подготовки данных обследования к анализу и повысить долю приёмов с диагностикой за один визит, обеспечив полную электронную фиксацию результатов приёма.

Разбор по SMART:

- **S — конкретность:** автоматизировать подготовку данных для врачебных решений: сбор и структурирование данных обследования, формирование рейтинга диагностических гипотез, подготовку проекта плана лечения. Не «улучшить медицину», а конкретные функции поддержки приёма.
- **M — измеримость:** время подготовки данных обследования к анализу — **с 15 до 5 минут**; доля приёмов, на которых предварительный диагноз сформулирован за один визит — **с 60% до 85%**; фиксация обследований, диагнозов и назначений в электронной БД — **100%** (исключить бумажные записи).
- **A — достижимость:** ПС реализуется как клиент-серверная система (АРМ врача + три серверных модуля) без разработки медицинских алгоритмов с нуля: история болезни и справочные данные приходят из внешней МИС, финальные решения остаются за врачом.
- **R — значимость:** рутинный поиск и сопоставление разнородных данных съедает время приёма и провоцирует ошибки; автоматизация подготовки данных освобождает время врача на собственно медицину.
- **T — ограниченность во времени:** срок достижения показателей — 6 месяцев после внедрения.

## 5. Задачи разработки

1. Разработать клиентскую часть — АРМ врача: ввод данных приёма (данные пациента, показания), отображение результатов (диагноз, план лечения).
2. Разработать серверные модули обработки: **модуль регистрации** (запрос карты во внешней МИС, оформление обследования), **модуль диагностики** (рейтинг диагностических гипотез), **модуль лечения** (проект плана лечения).
3. Обеспечить обмен данными с внешней МИС: медкарты пациентов, схожие обезличенные случаи.
4. Обеспечить локальное хранение результатов приёмов с защитой персональных данных (152-ФЗ).
